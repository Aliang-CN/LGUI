# FairyGUI-unity 改动台账

上游：FairyGUI-unity 提交 `8cc8f214cca79685532eef13372d0a4f74acdf08`（来源、范围见 `package/FairyGUI/SOURCE.md`）。**上游文件原则上一个字节不改**：LGUI 自己要的东西放在 LGUI 的程序集（`package/Runtime/`）里，用 FairyGUI 的扩展点接上（比如 `FontManager.RegisterFont`）。只有扩展点做不到、必须改上游文件的，记在这张表里：写清改了哪个文件、为什么、原文和现在的样子、怎么验证。

## 怎么升级上游

换提交以后，先把下表的文件恢复成新上游的原文，再按「现在」一栏重新改一遍；`tests/unit/unity/tmp-setup.test.mjs` 里记着上游原文，要一起换。

## LGUI 侧的适配

- `package/Runtime/Resources/LGUI/FairyGUI-TMP.mat`、`FairyGUI-TMP-Underlay.mat`：FairyGUI 的 TMP shader（`FairyGUI/Extensions/TextMeshPro/Shaders/FairyGUI-TMP.shader`，`Shader "FairyGUI/TextMeshPro/Distance Field"`）不在 Resources 里，`TMPFont` 用 `Shader.Find` 按名字找它。出包时 Unity 只带被引用的 shader，投影用的 `UNDERLAY_ON` 是 `shader_feature`，没有材质用到也会被剥掉。这两份材质放在 Resources 里、引用这个 shader（一份不开关键字、一份开 `UNDERLAY_ON`），出包就会带上 shader 和这两个变体。shader 文件本身不动、不挪。
- `package/Runtime/Platform/Fonts.cs` 的 `ProjectTMPFont`（`TMPFont` 的子类，项目字体注册的就是它）：上游 `TMPFont` 默认向 TMP 查 Medium 字重的字（`TMPFont.cs` 第 51 行），粗体查 Bold（第 316 行）。LGUI 运行时建的 TMP 字体只有一个字重、字重表是空的，TMP（com.unity.ugui 2.6.0）对非 Regular 字重只找替代字体，找不到就返回空，不从字体文件加字，结果字宽 0、什么都不画（Windows、Unity 6000.6.6f1 实测，0.4.1 文字全不显示的原因）。普通字用上游的 `fontWeight` 设成 Regular；粗体上游没有设字重的地方，子类在 `SetFormat` 之后把私有字段 `_fontWeight` 重设成 Regular（反射），`FontStyles.Bold` 和 `format.bold` 保留，粗体照旧由 shader 加粗、加宽字距（伪粗体）。字段找不到时注册字体直接抛错，不会静默画不出字。**升级上游时**：`tests/unit/unity/tmp-setup.test.mjs` 记着子类依赖的上游那几行（`_fontWeight` 字段、默认 Medium、粗体定成 Bold、查字用 `_fontWeight`），变了要红，照新上游重看一遍。
- 同一个 `ProjectTMPFont` 还把描边、投影从设计像素换成 TMP SDF 单位：上游 `TMPFont.UpdateGraphics` 把 `TextFormat.outline`（`strokeSize`）、`shadowOffset` 原样写进 shader 的 `_OutlineWidth`、`_UnderlayOffsetX/Y`，那是 SDF 范围的比例，不是像素（strokeSize 3 把字吃空，shadowOffset 7,7 被字的四边形裁掉）。上游 `TextField.OnPopulateMesh` 先 `SetFormat(格式, shrink 后的比例)` 再 `StartDraw`：子类在 `StartDraw` 里按缩后的字号换算，把用到的图集重新标成活动的，再调一次上游的 `Prepare` + `BuildGraphics`，让上游按换算后的值重算比例、留边和 shader 参数。主字体通过公开成员（`NGraphics.meshFactory`、`subInstances`、`NTexture.lastActive`、`TextField.textFormat`）接入；回退字体通过 U2 钩子按自身 FontAsset 转换，不复用主字体已换算的数。描边 = 字外的 dilate + 一样宽的 outline（和网页补丁 7 一样露在字外、不吃填充），投影按上游 ratioC 反算。超出 SDF 能画的范围时记 `LGUI-RT-183`（`lgui check` 先用 `LGUI-UI-081` 按字号的 7.5% 拦）。描边单位 `SdfOutlineUnit` 按 [字体验收 E](../../../../tests/unity/fonts/README.md) 实测；转换和图集尺寸修复不改变该常数或 7.5% 上限。**升级上游时**：`tests/unit/unity/tmp-setup.test.mjs` 记着子类依赖的上游那几行（`OnPopulateMesh` 里 `SetFormat` 紧接 `StartDraw`、`UpdateGraphics` 写 shader 参数、ratioA / ratioC 的算法、`CreateSubGraphics` 按 `lastActive` 挑图集和 U2 钩子），变了要红。
- `ProjectTMPFont.StartDraw` 最后为主 graphics 和所有已有 sub graphics 的 MPB 写 `_TextureWidth/Height`，值来自各自 `graphics.texture.nativeTexture` 的实际宽高，不改共享材质。TMP 动态图集先创建 1×1 Texture，再原地扩图；上游 NTexture 缓存可能仍是 1×1，原 `OnCreateNewMaterial` 用这个缓存值作投影 UV 分母。Windows 复现中真实图集 2048、缓存和材质分母 1、Texture Repeat，4 像素变成四个完整 UV 周期，采回原字形。这个修复通过现有 MPB 扩展点完成，不需要改 NTexture、预热字形或硬编码图集尺寸。材质参数采样必须按属性是否存在判断 MPB 覆盖与共享材质值，不能把未设置属性读到的零当成实际偏移；验证入口仍是[实际图集回归](../../../../tests/unity/fonts/atlas/README.md)。
